Targeted error

Each approach targets a limited number of error types, which are the targeted errors. [Paulheim, 2017] refers to the targeting of different errors as targeted information.

Most knowledge graphs use three types of assertions:

  • Instance assertions: define the type of an instance
  • Property-value assertions : define the relationship between two instances (instances of classes or datatypes)
  • Equality assertions : link two instances that describe the same object of discourse, also known as identity links

These assertions may contain syntactic or semantic errors, referred to as the error nature. The error source refers to the specific type of assertion that is affected, while the error type results from combining the error source with the error nature. It identifies which entity (subject, predicate, or object) in the triple is erroneous.

The erroneous entity is pinpointed through specific operands, which are defined by the associated operator. For instance, the isElementOf predicate expresses an instantiation relationship between an instance identifier i and a type t, both of which are operands.

Syntactic Errors

Syntactic errors violate formal syntax specifications that govern the allowed symbols and combinations in RDF serializations. These include formats such as Turtle, RDF/XML, datatypes defined by XML Schema (XSD), and identifiers conforming to W3C's IRI specification.

Semantic Errors

Semantic errors occur when assertions violate domain semantics or formal constraints. These constraints may be defined through ontologies or integrity rules, such as SHACL shapes. They describe desired graph structures and valid uses of concepts and properties.

Some formal violations may appear syntactic—for instance, a typo in a type name may result in a range violation. Likewise, regional spelling variations like “color” vs. “colour” may lead to invalid IRIs.

Semantic errors may also conflict with the intended domain of discourse. For example, the statement “Sydney is located in the United States” may be contextually wrong depending on the graph’s intended interpretation. In such cases, background knowledge is required to understand the domain context and validate assertions.
