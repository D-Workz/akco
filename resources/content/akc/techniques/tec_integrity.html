Integrity constraint-based

Integrity constraints validate knowledge graph (KG) assertions by checking them against expected semantic and syntactic features. These features include domain and range constraints, cardinalities, and supported entity types. Constraints are typically defined manually by domain experts.

Figure: Expressing Constraints Using SHACL

Figure 6: Manually defined integrity constraints demonstrates how SHACL constraints are defined in Turtle syntax for a knowledge graph (see Figure 1: Example KG. The shape CityConstraint targets nodes of type City using sh:NodeShape and sh:targetClass. It includes:

  • Range constraints: Defined using sh:class (IRI) or sh:datatype (e.g., xsd:string).
  • Cardinality constraints: Specified using sh:minCount and sh:maxCount.
  • population is optional, while officialCurrency is mandatory and must appear exactly once.

Constraint Languages and Tools

SHACL is a prominent constraint language supported by several tools:

  • RDFUnit: Translates SHACL constraints into Data Quality Test Patterns and then into SPARQL queries [Kontokostas et al., 2014].
  • VeriGraph: Targets schema.org-based KGs using DomainSpecifications to extend or restrict ontology semantics [Fensel et al., 2020a], [Simsek et al., 2020].
  • Validata: Uses ShEx and RDF Constraint Vocabulary (RDF-CV) to verify RDF data client-side [Baungard et al., 2015].
  • IDLab validatrr: Defines constraints using N3Logic rules and applies them via reasoning [De Meester et al., 2021].

Other constraint languages include:

  • ReSh: Developed by IBM for validating server resource descriptions [Ryman et al., 2013].
  • ShEx: Focuses on human readability and compact syntax [Boneva et al., 2014], [Prud'Hommeaux et al., 2014].

  2. A syntactic type mismatch for the population property.
  3. A missing mandatory officialCurrency property for the node newYork.

Constraint Application

Constraints can be applied through different methods:

  • SPARQL-based validation (e.g., RDFUnit [Kontokostas et al., 2014], VeriGraph [Fensel et al., 2020a], Schema Validator Tool [Simister et al., 2013]).
  • SPIN vocabulary for expressing constraints as SPARQL rules [Knublauch et al., 2011].
  • RDF-CV as an intermediate layer for ShEx tools [Eckert et al., 2015], [Hartmann, 2016].
  • Reasoning (e.g., IDLab validatrr [De Meester et al., 2021]).

Value-clustered Graph Functional Dependencies (VGFD) present a data-driven alternative by mining constraints from value similarities [Yu et al., 2011].

Constraint validation typically ends with a report listing violations, useful for further cleaning or hybrid validation steps [Chen et al., 2021].
