Integrity Constraint-Based Approaches

Integrity constraints validate knowledge graph (KG) assertions by checking them against expected semantic and syntactic features. These features include domain and range constraints, cardinalities, and supported entity types. Constraints are typically defined manually by domain experts.

Figure: Expressing Constraints Using SHACL

Figure tech_integrity_constraints demonstrates how SHACL constraints are defined in Turtle syntax for a knowledge graph (see Figure lst:sample_kg). The shape CityConstraint targets nodes of type City using sh:NodeShape and sh:targetClass. It includes:

  • Range constraints: Defined using sh:class (IRI) or sh:datatype (e.g., xsd:string).
  • Cardinality constraints: Specified using sh:minCount and sh:maxCount.
  • population is optional, while officialCurrency is mandatory and must appear exactly once.

Constraint Languages and Tools

SHACL is a prominent constraint language supported by several tools:

  • RDFUnit: Translates SHACL constraints into Data Quality Test Patterns and then into SPARQL queries [1].
  • VeriGraph: Targets schema.org-based KGs using DomainSpecifications to extend or restrict ontology semantics [2], [3].
  • Validata: Uses ShEx and RDF Constraint Vocabulary (RDF-CV) to verify RDF data client-side [4].
  • IDLab validatrr: Defines constraints using N3Logic rules and applies them via reasoning [5].

Other constraint languages include:

  • ReSh: Developed by IBM for validating server resource descriptions [6].
  • ShEx: Focuses on human readability and compact syntax [7], [8].

Figure: Validation Report

Figure tech_integrity_validation presents the output of applying SHACL constraints (from Figure tech_integrity_constraints) to the knowledge graph (Figure lst:sample_kg) using SHACL Playground. The report includes:

  • sh:ValidationResult objects for each violation
  • sh:focusNode, sh:resultPath, and sh:value to identify the issue
  • sh:sourceShape and sh:sourceConstraintComponent to explain the violated constraint

Examples of violations include:

  • A range error due to a datatype instead of an IRI in the officialCurrency property.
  • A syntactic type mismatch for the population property.
  • A missing mandatory officialCurrency property for the node newYork.

Constraint Application

Constraints can be applied through different methods:

  • SPARQL-based validation (e.g., RDFUnit [1], VeriGraph [2], Schema Validator Tool [9]).
  • SPIN vocabulary for expressing constraints as SPARQL rules [10].
  • RDF-CV as an intermediate layer for ShEx tools [11], [12].
  • Reasoning (e.g., IDLab validatrr [5]).

Value-clustered Graph Functional Dependencies (VGFD) present a data-driven alternative by mining constraints from value similarities [13].

Constraint validation typically ends with a report listing violations, useful for further cleaning or hybrid validation steps [14].
