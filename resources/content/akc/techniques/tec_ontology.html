Ontology-based

Ontology-based approaches use formal ontologies as background knowledge to detect and correct assertion errors in knowledge graphs. These ontologies, defined in languages like RDFS or OWL, describe the semantics of classes, properties, and their relationships. When applied systematically to a graph, this process is known as reasoning.

Figure: Ontology-based reasoning

Figure 8 illustrates a generalized workflow for reasoning-based techniques. The workflow begins with the ontology and the input assertions (1). Reasoning can be conducted under either the open-world assumption (OWA) or the closed-world assumption (CWA):

  • Open-world assumption (OWA): Anything not stated is considered unknown, not false. For instance, an entity can be both Person and City unless explicitly forbidden. Disjointness axioms (e.g., owl:disjointWith) are used to enforce contradictions.
  • Closed-world assumption (CWA): Anything not known is assumed false. Here, ontology restrictions can be used as constraints, similar to integrity constraint checking.

If disjointness axioms are not present, they can be added via optional enrichment (2). This can be done in two ways:

  • Machine learning methods: These include rule mining to find disjoint class pairs or vector-space models that define disjointness based on low property similarity [Töpper et al., 2012].
  • Ontology alignment: Enrich the ontology by aligning it with foundational ontologies like DOLCE-Zero or UMBEL [Zhaohua et al., 2012].

The reasoner then derives implicit knowledge from explicit assertions (3). This process, known as closure computation, results in a graph where all entailed types and relationships are made explicit. If this process introduces contradictions, the output includes inconsistent contextual graphs. For example, if sydney is inferred to be both a Person and a City (which are disjoint), an inconsistency is flagged.

These inconsistencies must be analyzed to locate the actual error. Possible corrections include:

  • Removing or relaxing disjointness axioms
  • Adjusting domain/range assignments
  • Replacing a misused property [Baader et al., 2022]

Under the closed-world assumption, violations are identified directly using ontology-based constraints (4). In this mode, tools like Astrea can generate SHACL constraints from an ontology for validation purposes.

Correcting Equality Assertion Errors

Some ontology-based methods also address semantic errors in equality assertions. These approaches identify when equality relations like owl:sameAs are too strict and suggest alternative identity types based on context. Proposed solutions include:

  • Identity Ontology (IO): Introduces nuanced identity properties derived from SKOS axioms [McCusker et al., 2010].
  • Identity on the Web (IOTW): Uses context-specific sub-properties of owl:sameAs [Beek et al., 2016].
  • DECIDE: Suggests named-graph-scoped equality links for context-sensitive identity [Raad et al., 2017].

Entity Correction via Ontology Matching

Ontology matching techniques are used to replace non-existing or misaligned entity names with suitable equivalents from related ontologies. Data-driven systems like LaKERMap and OLaLa use large language models (LLMs) for scalable alignment [Wang, 2023], [Hertling et al., 2023].
